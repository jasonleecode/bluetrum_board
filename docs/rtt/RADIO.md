# S2 / 红外收音机应用

综合固件默认启用 `BSP_USING_RADIO_APP`，应用位于
[app_radio.c](../../rtt/bsp/app/app_radio.c)。复用主线程的按键扫描、FM 驱动、
红外事件队列和红灯 PWM，不创建新线程或音频缓冲池。

## 操作

| 输入 | 行为 |
| --- | --- |
| S2 短按 | 同时开启收音机和红色呼吸灯；每次启动恢复 **97.4 MHz、15% 音量** |
| S2 再短按 | 停止 FM、关闭红外接收、红灯熄灭 |
| 遥控器上 / 下 | 音量增加 / 减少 **5 个百分点**，限制在 0–100% |
| 遥控器右 / 左 | 频率增加 / 减少 **0.1 MHz** |
| 上 / 下长按 | 收到完整重复帧后，从按住 500 ms 开始，每至少 250 ms 调整一次 |
| 左 / 右长按 | 只在首次 DOWN 时调频，不连续跳频 |

上电保持关闭。S2 按住只触发一次，S3/S4 保留原有按键事件。
调频范围为 **87.5–108.0 MHz**：108.0 向右到 87.5，87.5 向左到 108.0。
这是固定步进调频，不是自动搜台。快速重复按同一个遥控键可能被底层识别为长按重复，
测试独立短按时建议间隔约 1 秒。

## 接线和遥控器

- V2.0 的 P1 **3–4** 短接红灯 PE1，P1 **1–2** 短接 IRDA→PE6。
- 使用板上 CTIA 3.5 mm 耳机口；耳机线同时作为 FM 天线。
- 当前按键映射对应已实测的扫地机器人遥控器（NEC 地址 `0x4c`）：

| 按键 | 完整帧 |
| --- | --- |
| 上 | `0xb54ab34c` |
| 下 | `0xad52b34c` |
| 右 | `0xbe41b34c` |
| 左 | `0xe619b34c` |

其他地址、命令或释放事件不会执行调节。更换遥控器需重新识别并修改映射；
原始接收记录见 [IR.md](IR.md)。

## 串口与资源共存

```text
radio status
radio start
radio stop
fmrx status
led status
irrx status
```

`radio start/stop` 提交请求，由主循环执行；用 `radio status` 查询实际 `on` 状态、
目标 `wanted`、频率、音量、已执行遥控操作数和错误码。
启动成功后才开启呼吸灯；FM、红外或 LED 初始化失败会报告错误并清理已启动的资源。
运行期间若 LED 出错或 FM 因调谐超时关闭，应用也会关闭关联功能。
`ir0` 在使用前打开，停止或启动失败后关闭，避免泄漏设备引用。

FM 与蓝牙目前互斥。若本次开机已启动蓝牙，S2 启动 FM 会返回忙，红灯保持熄灭；
需要复位后先使用 FM。PCM 播放占用 DAC 时也不能启动 FM。
应用运行时是红外队列的读取者，不要同时用 `irrx read/watch` 消费同一队列；
`irrx status` 不消费事件，可以使用。独立驱动调试前先 `radio stop`。

FM 控制增加不等待锁的入口 `ab32_fmrx_try_control()`：锁被其他线程占用时返回
`-EAGAIN`，应用保留待执行的遥控操作，继续更新按键和呼吸灯。
取得锁之后，驱动的同步 PLL 校准仍可能占用最多 100 ms 的等待阶段；不是异步调谐。
低层 `fmrx stop` 会在应用下次状态同步时关闭呼吸灯和红外；`fmrx volume/tune`
仍能修改硬件，但正常操作应使用应用入口。

## 验证

```sh
python3 tools/rtt/test_radio.py
python3 tools/rtt/test_drivers.py
python3 tools/rtt/check_builds.py default led
python3 tools/rtt/memory_report.py
```

应用模型覆盖 S2 启停和重启默认值、四个原始键码、频段循环、音量边界、长按限速、
tick 回绕、锁忙重试、FM/LED/IR 失败清理、IR 设备打开/关闭及诊断控制后的状态同步。
原 LED 独立配置仍可编译；关闭 `BSP_USING_RADIO_APP` 后恢复 S2 只控制呼吸灯。

实板串口已验证 `radio start/stop`：FM 97.4 MHz / 15%、呼吸灯与 IR 同步启停，
停止后 `ir0` 引用为零；测试前后 used 堆均为 9376 字节，可用堆 9256 字节，
主线程栈最高使用约 37%。以上堆数据对应加入 RF 电容诊断前的应用镜像；
最新镜像预算见 [MEMORY.md](MEMORY.md)。实体 S2 已触发应用，串口也记录到遥控音量操作，
但本轮尚未逐项完成四个实体方向键的独立验收。

### FM 音频隔离测试（2026-11-03）

**广播接收尚未通过：S2 开启后用户听到脉冲状刺耳声，不能把控制命令成功视为收音成功。**

| 测试 | 结果 |
| --- | --- |
| 仅 FM 97.4 MHz、3% 音量，呼吸灯和红外关闭 | 用户仍听到同样的脉冲刺耳声 |
| 同一路 38 kHz DAC，固定测试音、3% 音量、约 10 秒 | 用户确认清晰稳定的“嘟”声 |
| 静音比较 97.3、97.4、97.5 MHz 等频点 | 原始 RSSI 未显示明确的 97.4 MHz 峰值 |
| 静音、97.4 MHz，输入电容参数 0–31，各读三次 RSSI | 未获得支持更改默认值的证据，已恢复 0 并停止 FM |

这些结果缩小到 FM 接收及其音频数据路径，但不能据此确定是天线、环境、
射频初始化还是数字解调的问题。DAC 固定音正常也不能替代 FM 数据链路验证。
电容扫描只有一次顺序扫描，未分离时间/环境变化；RSSI 为未校准原始值，不换算 dBu。
测试结束收音机、红灯和红外均关闭，下一次 S2 仍按用户指定的 97.4 MHz / 15% 启动。
完整记录见 [radio-rtt-hardware.json](../lib-analysis/generated/recovery/radio-rtt-hardware.json)。

独立诊断前先执行 `radio stop`，等待 `radio status` 显示 `on=0`：

```text
fmrx tone 3
fmrx volume 0
fmrx start 97400
fmrx rssi
fmrx cap 0
fmrx stop
```

`fmrx tone [0..20]` 只播放固定音，约 10 秒后停止；省略音量仍兼容旧命令的 20%。
`fmrx cap <0..31>` 仅在 FM 开启时生效，调用已恢复的 RF 电容接口；
下一次 FM 上电会恢复 0。它用于诊断，不是搜台命令，也未改变应用默认参数。
